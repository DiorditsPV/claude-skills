# Пилот skill-first: youtube-breakdown как скилл-репозиторий с данными

Дата: 2026-07-07. Статус: утверждён, реализован в этом репозитории.

## Контекст и цель

По мотивам доклада Krestnikov «Скиллы на базе git — новая память AI-агентов»
(разбор: `skills/youtube-breakdown/data/breakdowns/git-skills-memory/OVERVIEW.md`, ветка `data`).
Ключевая идея: скилл = короткое описание + длинное описание + инструменты + **данные**,
всё в git — данные подтягиваются в контекст в момент активации скилла и становятся памятью агента.

Пилот: конвертировать существующий скилл `youtube-breakdown` (раньше — stateless-команда в dotfiles,
данные падали в `~/dev/docs` без связи со скиллом) в data-skill. Дорожная карта после пилота:
1. кодифицировать выводы в канон (`skill-new`/`skill-audit`): тип «data-skill», протокол pull/push, INDEX.md;
2. новый data-skill с нуля по обновлённому канону;
3. Curator-слой (pruning + консолидация библиотеки ~70 скиллов).

## Решения (приняты в диалоге)

1. **Пилот** — `youtube-breakdown` (данные нечувствительные, накопление уже происходит, есть ценность кросс-ссылок).
2. **Один репозиторий** `~/dev/claude-skills` — публичный marketplace всех нерабочих скиллов.
3. **Данные не публикуются.** Разделение ветками, а не отдельным репо:
   - `main` — код скиллов, `skills/*/data/` пустые (`.gitkeep`); пушится только в публичный `origin`;
   - `data` — рабочая ветка (код + данные); пушится только в приватный remote `private`
     (`DiorditsPV/claude-skills-data`) — синхронизация машин и бэкап без публикации.
4. **Односторонний поток main→data.** На `data` коммитятся только `skills/*/data/**`
   (pre-commit hook; merge-коммиты пропускаются). Код правится на `main`, затем `merge main→data`.
   `data→main` не сливается никогда — утечка данных в публичную ветку исключена механически.
   Pre-push hook блокирует `data→origin`.

## Структура

```
claude-skills/
├─ .claude-plugin/{plugin.json, marketplace.json}   # репо = один плагин + marketplace
├─ .githooks/{pre-commit, pre-push}                 # git config core.hooksPath .githooks
├─ docs/specs/                                      # этот документ
└─ skills/youtube-breakdown/
   ├─ SKILL.md                                      # процесс + протокол данных
   ├─ scripts/vtt_to_transcript.py
   └─ data/                                         # только на ветке data
      ├─ INDEX.md                                   # реестр разборов + кросс-ссылки
      └─ breakdowns/<slug>/                         # OVERVIEW.md, транскрипты, метаданные
```

## Скилл как процесс (изменения против старой версии)

- **Протокол данных**: `git pull private data` в начале, `commit+push` сразу после — два обязательных
  правила скилл-репозитория из доклада.
- **Память на вход**: перед разбором читается `data/INDEX.md`; в OVERVIEW.md добавлена секция
  «Связь с прежними разборами»; после разбора INDEX.md обновляется.
- **Ответы из памяти**: новый режим — вопросы «что я смотрел про X» отвечаются двухэтапной загрузкой
  (INDEX.md → нужные OVERVIEW.md → транскрипты только при необходимости), без пересмотра роликов.
- Установка скилла из marketplace даёт пустой `data/` — скилл бутстрапит INDEX.md при первом разборе.

## Миграция

Существующие разборы (`~/dev/docs/instrumenty/youtube/{loop-engineer, git-skills-memory}`)
скопированы в `data/breakdowns/` на ветке `data`, построен первый INDEX.md.
Оригиналы в `~/dev/docs` не удалены (архив). Старый скилл из `~/.claude/skills/youtube-breakdown`
заменён симлинком на этот репозиторий.

## Риски и ограничения

- Хуки не клонируются автоматически — на новой машине обязателен `git config core.hooksPath .githooks`
  (зафиксировано в README; при желании добавить в bootstrap dotfiles).
- Защита хуками локальная; страховка на стороне GitHub — ветка `data` физически живёт в другом
  (приватном) репозитории, в `origin` её reference никогда не создаётся.
- Рост данных: транскрипты ~0.5 МБ на ролик — для git ок; при десятках гигабайт (кейсы уровня ДНК)
  понадобится LFS или вынос тяжёлых артефактов.
