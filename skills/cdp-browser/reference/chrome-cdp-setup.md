# Чистый Chrome с CDP-портом: устройство и обоснование

Справочник к скиллу `cdp-browser`. Объясняет, почему браузер поднимается именно так,
что делает каждый флаг и как настроить MCP-путь. Сами команды автоматизированы
в `scripts/ensure.sh` и `scripts/cdp.mjs` — здесь разбор, а не второй рецепт.

Проверено на macOS, Chrome 149.

---

## 1. Почему дефолтная настройка не подходит

MCP-сервер `chrome-devtools` по умолчанию сам поднимает Chrome с флагом `--enable-automation`,
из-за чего `navigator.webdriver` становится `true`. Анти-бот-системы это видят и отдают заглушку
(Server error / капчу) вместо контента. IP и машина при этом те же, что у обычного браузера —
флагируется именно **фингерпринт автоматизации**, а не сеть.

Отсюда правило: браузером должен управлять инстанс, **не запущенный в режиме автоматизации**.
Достигается запуском Chrome без automation-флагов и подключением к нему по отладочному порту.

> ⚠️ Не маскировать драйвер (подмена `navigator.webdriver`, stealth-плагины, спуф фингерпринта).
> Это обход bot-detection, гонка вооружений, и одним патчем не лечится — проверяется десяток
> сигналов (наличие CDP, `Runtime.enable`, тайминги, canvas/WebGL и т.д.). Правильный путь —
> браузер, который **изначально** чистый.

## 2. Параметры запуска и обоснование каждого

Именно эту команду собирает `scripts/ensure.sh`:

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --user-data-dir=/tmp/chrome-cdp \
  --remote-debugging-port=9222 \
  --no-first-run --no-default-browser-check &
```

| Параметр                        | Значение                                     | Почему так                                                                                                                              |
| ------------------------------- | -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `--remote-debugging-port`       | напр. `9222`                                 | Открывает CDP-эндпоинт для подключения. Без него MCP вынужден сам поднимать свой (automation-)Chrome.                                    |
| `--user-data-dir`               | **отдельная** папка, напр. `/tmp/chrome-cdp` | С Chrome 136+ порт **игнорируется на дефолтном профиле**. Только отдельный профиль заставляет порт работать.                             |
| `--no-first-run`                | —                                            | Подавляет мастер первого запуска, чтобы Chrome сразу открыл нужную страницу.                                                             |
| `--no-default-browser-check`    | —                                            | Убирает диалог «сделать браузером по умолчанию», мешающий автоматическому старту.                                                        |
| `--browser-url` (в конфиге MCP) | `http://127.0.0.1:9222`                      | Говорит MCP подключаться к уже запущенному браузеру, а не поднимать свой. Именно это и даёт `navigator.webdriver = false`.               |

**Почему отдельный профиль, а не дефолтный.** На дефолтном профиле (с вашими логинами и куками)
Chrome 136+ намеренно не отдаёт отладочный порт — это защита от кражи сессии через CDP. Поэтому
для программного доступа всегда поднимается **изолированный** профиль. Минус — он чистый
(без кук и истории); для большинства задач этого достаточно, так как блок снимается уже самим
`navigator.webdriver = false`. Если нужна авторизованная сессия — скопируйте свой профиль
в отдельную папку и запускайте **копию** с портом.

**Почему `--browser-url`, а не дефолтный запуск.** Без этого аргумента MCP игнорирует ваш чистый
Chrome и стартует собственный с automation-флагами — то есть возвращает исходную проблему.
`--browser-url` переключает MCP в режим «присоединиться к существующему браузеру».

Проверить версию Chrome (чтобы знать, обязателен ли отдельный профиль):
```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --version
```

Путь к бинарнику зашит в `ensure.sh` под macOS; на другой ОС переопределяется через `CHROME_BIN`.

## 3. Хранит ли этот браузер cookies

Да. `--user-data-dir` — это **полноценный профиль Chrome**: в нём сохраняются cookies,
`localStorage`, `IndexedDB`, история и кэш — ровно как в обычном браузере. Два нюанса:

- **Профиль изолирован.** Это отдельная папка, не связанная с основным Chrome. Логины,
  сделанные в этом окне, не появляются в основном браузере и наоборот. Делиться куками
  с личным профилем по CDP нельзя — это и есть та самая защита Chrome 136+.
- **По умолчанию cookies эфемерны.** Без `--persist` скилл использует `/tmp/chrome-cdp`
  и очищает профиль при каждом старте. Вдобавок `/tmp` периодически чистится самой macOS
  и обнуляется при перезагрузке. То есть каждая сессия начинается «с нуля».

**Чтобы сохранять сессии между запусками** (один раз залогиниться и переиспользовать) —
запускать с `--persist`: профиль переезжает в стабильный `~/.cache/chrome-cdp-profile`
и не очищается. В открывшемся окне достаточно один раз вручную войти на нужные сайты;
на последующих запусках сессия подхватится автоматически.

> 🔐 Такой профиль хранит **реальные авторизационные cookies на диске**. Относитесь к папке
> как к залогиненному браузеру: не выкладывайте в общий доступ, не коммитьте, при
> необходимости удаляйте.

## 4. Если порт не поднимается

Типичная причина — «забытый» automation-инстанс, который держит свой профиль:

```bash
# найти процессы на профиле devtools-mcp
ps aux | grep "chrome-devtools-mcp/chrome-profile" | grep -v grep
# освободить профиль
pkill -f "chrome-devtools-mcp/chrome-profile"
```

Проверка, что порт реально слушается (это же делает `ensure.sh` в конце):
```bash
curl -s http://127.0.0.1:9222/json/version
# должен вернуть JSON с "Browser": "Chrome/..."
```

Ответ подтверждает, что профиль не дефолтный и порт открыт. Если пусто —
профиль дефолтный (см. §2) либо Chrome не стартовал.

## 5. MCP-путь: настройка `chrome-devtools` на этот порт

Скилл по умолчанию работает через прямой CDP (`scripts/cdp.mjs`), потому что это не требует
рестарта сессии. MCP-путь нужен, если вы хотите пользоваться инструментами
`mcp__chrome-devtools__*` — тогда сервер надо один раз настроить.

В конфиге Claude Code (`~/.claude.json`) найти сервер `chrome-devtools` в `mcpServers`
и добавить `--browser-url`:

```jsonc
"chrome-devtools": {
  "type": "stdio",
  "command": "npx",
  "args": ["-y", "chrome-devtools-mcp@latest", "--browser-url=http://127.0.0.1:9222"],
  "env": {}
}
```

Затем **перезапустить Claude Code**: живой MCP-сервер не подхватывает новые аргументы
без рестарта сессии.

Важно: при такой конфигурации браузер на `9222` должен быть запущен **до** старта сессии,
иначе MCP не подключится. Скилл не может ни перезапустить Claude Code, ни перечитать
аргументы MCP-сервера — поэтому этот путь требует ручной подготовки, а дефолт — прямой CDP.

Проверка чистоты после настройки: в `evaluate_script` выполнить `() => navigator.webdriver`
→ должно быть `false`, а целевая страница должна отдавать реальный контент.
