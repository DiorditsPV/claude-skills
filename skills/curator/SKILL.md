# curator

Обслуживание библиотеки скиллов: отчёт → предложения → применение одобренного.
Мотивация — по Krestnikov (Hermes Curator): короткие описания сотни скиллов
выжигают контекст; неиспользуемое деактивируется, мелкое консолидируется.

Пути — относительно директории скилла (`SKILL_DIR`, symlink разрешай через реальный путь).

## Периметр

Анализируется весь `~/.claude/skills`. Изменения применяются только к:
- **локальным** скиллам (обычные директории) → архив в `~/.claude/skills-archive/YYYY-MM/`;
- **скиллам claude-skills** (симлинки в `~/dev/claude-skills`) → `git mv` в `archive/` репозитория на `main`.

**Не трогать никогда** (только рекомендации текстом): симлинки в рабочие репо и
приватные KB, плагины (`~/.claude/plugins`, скиллы с префиксом `plugin:`).

## Протокол данных

Журнал решений — `data/log.md` (append-only, на git-ветке `data`, пуш только в remote `private`):
перед работой `git -C "$SKILL_DIR/../.." pull private data`; после — commit (`data(curator): ...`) + push.
Журнал нужен двухступенчатому pruning: без записи «когда деактивирован» нет ступени «90 дней → архив».

## Режим 1: отчёт

1. Статистика использования: `python3 "$SKILL_DIR/scripts/usage_stats.py"` (TSV: skill, count, first, last).
2. Инвентарь `~/.claude/skills`: имя, тип (local / claude-skills / work / plugin), длина description из frontmatter.
3. Сведи в таблицу. **Честность данных:** логи покрывают ограниченную историю — «нет упоминаний в логах» помечай отдельно от «давно не использовался»; не выдавай отсутствие данных за неиспользование.
4. Итог: сколько скиллов, сколько байт описаний уходит в контекст, топ кандидатов ниже.

## Режим 2: предложения

- **Архив:** не использовался >30 дней по логам (или ни разу при покрытии логов >30 дней). Для каждого — имя, тип, последнее использование, что произойдёт (куда переедет).
- **Консолидация:** мелкие смежные скиллы (семейства по префиксу/домену, пары «создать/проверить», дублирующие триггеры). Предлагай попарно, с черновиком объединённого description. Объединение — только внутри одного типа (local с local и т.п.).
- Для work/plugin — отдельная секция «рекомендации без действий».

Покажи предложения списком и жди явного одобрения по пунктам (можно частичного).

## Режим 3: применение (только одобренное)

- Локальный: `mkdir -p ~/.claude/skills-archive/$(date +%Y-%m)` → `mv` туда директорию скилла.
- claude-skills: на `main` — `git mv skills/<name> archive/<name>`, убрать строку из README, commit+push origin, merge `main→data`, push private.
- Консолидация: собери объединённый SKILL.md, покажи целиком, после одобрения запиши новый и заархивируй исходные (как выше).
- Каждое действие (и каждый отказ) — строка в `data/log.md`: `YYYY-MM-DD · skill · archived/merged/declined · причина`.
- Финал: протокол данных (commit+push), напомни про `/reload-skills`.

## Восстановление
Локальный — `mv` обратно из архива; claude-skills — `git mv` из `archive/` на `main`. Упомяни это в отчёте, чтобы решения не казались необратимыми.

## Анти-паттерны
- Не применяй ничего без явного одобрения конкретного пункта.
- Не удаляй файлы — только перемещение в архив.
- Не трогай work-скиллы и плагины, даже по просьбе «прибери всё» — сначала переспроси.
- Не консолидируй отлаженные крупные скиллы ради красоты — цель только снижение расхода контекста.
