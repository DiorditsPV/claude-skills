# curator

Обслуживание библиотеки скиллов: отчёт → предложения → применение одобренного.
Мотивация — по Krestnikov (Hermes Curator): короткие описания сотни скиллов
выжигают контекст; неиспользуемое деактивируется, мелкое консолидируется.

Пути — относительно директории скилла (`SKILL_DIR`, symlink разрешай через реальный путь).

## Периметр

Анализируется весь перечень скиллов, видимый в сессии, тремя источниками:
- глобальные `~/.claude/skills` (local-директории и симлинки);
- project-scope скиллы рабочей директории — `<cwd>/.claude/skills`
  (обычно симлинки в KB проекта, напр. `.claude/rvi/skills`);
- плагины (`~/.claude/plugins/cache/**`, в списке сессии с префиксом `<plugin>:`).

Изменения куратор применяет сам только к:
- **локальным** скиллам (обычные директории) → архив в `~/.claude/skills-archive/YYYY-MM/`;
- **скиллам claude-skills** (симлинки в `~/dev/claude-skills`) → `git mv` в `archive/` репозитория на `main`.

Work-скиллы и плагины по умолчанию — только рекомендации. По явному решению
пользователя допустимы точечные действия (см. Режим 3); массовое «прибери всё»
на них не распространяется — сначала переспроси.

## Протокол данных

Журнал решений — `data/log.md` (append-only, на git-ветке `data`, пуш только в remote `private`):
перед работой `git -C "$SKILL_DIR/../.." pull private data`; после — commit (`data(curator): ...`) + push.
Журнал нужен двухступенчатому pruning: без записи «когда деактивирован» нет ступени «90 дней → архив».

## Режим 1: отчёт

1. Статистика использования: `python3 "$SKILL_DIR/scripts/usage_stats.py"` (TSV: skill, count, first, last).
2. Инвентарь всех трёх источников периметра: имя, тип (local / claude-skills / work / plugin),
   длина description из frontmatter.
3. Сведи в таблицу (можно по группам). **Честность данных:**
   - логи покрывают ограниченную историю — «нет упоминаний в логах» помечай отдельно
     от «давно не использовался»; не выдавай отсутствие данных за неиспользование;
   - ренеймы: вызовы старого и нового имени суммируй как один скилл
     (ренейм-волны project-скиллов, напр. `task-rvi` → `rvi-task`);
   - cron: скиллы, запускаемые джобами (`~/.config/claude-cron/jobs/*.json`),
     в session-логах не видны — сверь с перечнем живых джоб, прежде чем
     объявлять скилл неиспользуемым;
   - скиллы, вызываемые изнутри других скиллов/сабагентов (цепочки плагинов),
     тоже могут не попадать в логи — помечай.
4. Итог: сколько скиллов и байт описаний уходит в контекст — по группам и суммарно,
   топ кандидатов ниже.

## Режим 2: предложения

- **Архив:** не использовался >30 дней по логам (или ни разу при покрытии логов >30 дней).
  Для каждого — имя, тип, последнее использование, что произойдёт (куда переедет).
- **Консолидация:** мелкие смежные скиллы (семейства по префиксу/домену, пары
  «создать/проверить», дублирующие триггеры). Предлагай попарно, с черновиком
  объединённого description. Объединение — только внутри одного типа (local с local и т.п.).
- Для work/plugin — отдельная секция «рекомендации без действий»; действием они
  становятся только после явного решения пользователя по конкретному скиллу.
- Решённое не переоткрывать: отказ, зафиксированный в `data/log.md`, действует —
  повторно предлагай только при новом сигнале.

Покажи предложения списком и жди явного одобрения по пунктам (можно частичного).

## Режим 3: применение (только одобренное)

- Локальный: `mkdir -p ~/.claude/skills-archive/$(date +%Y-%m)` → `mv` туда директорию скилла.
- claude-skills: на `main` — `git mv skills/<name> archive/<name>`, убрать строку из README,
  commit+push origin, merge `main→data`, push private.
- Плагин (по явному решению пользователя): ключ `"<plugin>:<skill>": "off"` в
  `skillOverrides` в `~/.claude/settings.json` — плагин не трогается, обратимо
  удалением ключа; после — проверить валидность JSON.
- Work-скилл (по явному решению пользователя): правка через канал его KB-репо —
  `git rm`/архив внутри KB, коммит **только своих файлов** (в KB может идти
  параллельная работа на другой ветке), симлинк из `<cwd>/.claude/skills` снять,
  упоминания вычистить (gateway/INDEX KB, CLAUDE.local.md и т.п.); push — по
  каналу KB, не самовольно.
- Консолидация: собери объединённый SKILL.md, покажи целиком, после одобрения
  запиши новый и заархивируй исходные (как выше).
- Каждое действие (и каждый отказ) — строка в `data/log.md`:
  `YYYY-MM-DD · skill · archived/merged/off/removed/declined · причина`.
- Финал: протокол данных (commit+push), напомни про `/reload-skills`.

## Восстановление
Локальный — `mv` обратно из архива; claude-skills — `git mv` из `archive/` на `main`;
плагин — удалить ключ из `skillOverrides`. Упомяни это в отчёте, чтобы решения
не казались необратимыми.

## Анти-паттерны
- Не применяй ничего без явного одобрения конкретного пункта.
- Не удаляй файлы — только перемещение в архив (исключение: явное «удали» от
  пользователя по work-скиллу — тогда git-история и есть архив).
- Не трогай work-скиллы и плагины по общей просьбе «прибери всё» — сначала переспроси.
- Не консолидируй отлаженные крупные скиллы ради красоты — цель только снижение расхода контекста.
