# curator

Единый пайплайн обслуживания инструментария сессии: собрать данные → отчёт с
предложениями по активности → включить/выключить одобренное. Мотивация — по
Krestnikov (Hermes Curator): короткие описания сотни скиллов выжигают контекст;
неиспользуемое деактивируется, мелкое консолидируется.

Пути — относительно директории скилла (`SKILL_DIR`, symlink разрешай через реальный путь).

## Уровни

| Уровень | Где живёт | Выключить | Вернуть |
|---|---|---|---|
| **Глобальные** | `~/.claude/skills`: local-директории и симлинки в `~/dev/claude-skills` | local → `mv` в `~/.claude/skills-archive/YYYY-MM/`; claude-skills → `git mv` в `archive/` на `main` (+строка из README, merge `main→data`) | `mv`/`git mv` обратно + симлинк |
| **Рабочие** | `<cwd>/.claude/skills` — симлинки в KB проекта (напр. `.claude/rvi/skills`) | через канал KB-репо: `git rm`/архив в KB, коммит **только своих файлов** (в KB может идти параллельная работа), симлинк снять, упоминания вычистить (gateway/INDEX KB, CLAUDE.local.md); push — по каналу KB | восстановление в KB + симлинк |
| **Плагины** | `~/.claude/plugins/cache/<repo>/<plugin>`; включённые — `enabledPlugins` в `~/.claude/settings.json` | точечно скилл: `"<plugin>:<skill>": "off"` в `skillOverrides` (`~/.claude/settings.json`), после — проверить валидность JSON; плагин целиком — руками пользователя через `/plugins` | удалить ключ из `skillOverrides` |
| **MCP-серверы** | `mcpServers` в `~/.claude.json` (+ project-серверы в `projects.*` там же) | убрать сервер из конфига (`claude mcp remove` или правка `~/.claude.json` с проверкой JSON) | вернуть в конфиг; конфиг сервера сохранить в журнале при снятии |

Плагины и MCP куратор не архивирует — только мониторинг и точечные
переключения; массовое «прибери всё» на рабочие/плагины/MCP не
распространяется — сначала переспроси.

## Пайплайн

Один прогон, три этапа; единственная остановка — гейт после этапа 2.

### 1. Сбор данных

- скиллы: `python3 "$SKILL_DIR/scripts/usage_stats.py"` (TSV: name, count, first, last);
- MCP: `usage_stats.py --mcp` (вызовы `mcp__*` по серверам) + перечень настроенных серверов из конфига — сводить «настроен» × «использовался»;
- инвентарь скиллов обоих уровней: имя, уровень/тип, длина description из frontmatter;
- плагины: установленные (cache), включённые (`enabledPlugins`), их скиллы уже в статистике по префиксу `<plugin>:`;
- текущее выключенное: `skillOverrides` в `~/.claude/settings.json`.

**Честность данных:**
- логи покрывают ограниченную историю — «нет упоминаний» помечай отдельно от «давно не использовался»;
- ренеймы: вызовы старого и нового имени суммируй как один скилл (напр. `task-rvi` → `rvi-task`);
- cron: скиллы, запускаемые джобами (`~/.config/claude-cron/jobs/*.json`), в session-логах не видны — сверь с перечнем живых джоб;
- вызовы изнутри других скиллов/сабагентов (цепочки плагинов) тоже могут не попадать в логи — помечай.

### 2. Отчёт и предложения

- Таблицы по уровням: рабочие / глобальные / плагины / MCP; итог — сколько
  скиллов и байт описаний уходит в контекст, по группам и суммарно.
- Предложения об изменении активности:
  - **выключить** — >30 дней без использования (или 0 упоминаний при покрытии >30 дней), с указанием уровня и механизма;
  - **вернуть** — выключенное/архивное, по которому снова появился спрос;
  - **консолидировать** — мелкие смежные (семейства по префиксу/домену, пары «создать/проверить», дублирующие триггеры), попарно, с черновиком объединённого description; только внутри одного уровня и типа;
  - MCP-серверы без вызовов за покрытие — кандидаты на снятие из конфига.
- Решённое не переоткрывать: отказ, зафиксированный в `data/log.md`, действует — повторно предлагай только при новом сигнале.
- **СТОП**: жди явного решения по пунктам (можно частичного). Активность меняется только по требованию пользователя — как выключение, так и возврат.

### 3. Применение (только одобренное)

- Механизм — по таблице уровней. Консолидация: объединённый SKILL.md целиком на
  согласование → записать новый, исходные в архив.
- Каждое действие (и каждый отказ) — строка в `data/log.md`:
  `YYYY-MM-DD · name · archived/merged/off/on/removed/declined · причина`.
- Финал: протокол данных (commit+push), напомни про `/reload-skills`
  (изменения MCP-конфига подхватываются только перезапуском сессии).

## Протокол данных

Журнал решений — `data/log.md` (append-only, на git-ветке `data`, пуш только в remote `private`):
перед работой `git -C "$SKILL_DIR/../.." pull private data`; после — commit (`data(curator): ...`) + push.
Журнал нужен двухступенчатому pruning: без записи «когда деактивирован» нет ступени «90 дней → архив».

## Анти-паттерны

- Не применяй ничего без явного одобрения конкретного пункта.
- Не удаляй файлы — только архив/off (исключение: явное «удали» от пользователя — тогда git-история и есть архив).
- Не консолидируй отлаженные крупные скиллы ради красоты — цель только снижение расхода контекста.
- Не выдавай отсутствие данных за неиспользование.
