# design-funnel

Воронка выбора дизайна: много непохожих вариантов → отбор → общая ДНК выбранного →
следующий круг из этой ДНК. Повторяется, пока не останется то, что реализуют.

## Когда применять

- Пользователь не может описать словами, чего хочет, и словесные вопросы буксуют.
- Первая версия оформления не понравилась, а причина сформулирована как «не то».
- Нужно выбрать направление, а не отшлифовать уже выбранное.

Не применять, когда направление уже задано и нужно его аккуратно исполнить — это
frontend-design. И когда вопрос по сути текстовый (что писать, какие разделы) —
это разговор, а не показ.

## Перед началом

1. **Зафиксируй исходное состояние тегом** — `git tag -a v1-<что-было> -m "…"` и
   запушь. Круги идут быстро, откат должен быть в одну команду.
2. **Подними вкладку-компаньон** (из `superpowers:brainstorming`):
   `scripts/start-server.sh --project-dir <проект> --open`. Браузер обязателен:
   выбор делается глазами, терминал для этого не годится.
3. **Выбери опорный фрагмент** — один и тот же кусок интерфейса, на котором будут
   собраны все варианты. Обычно первый экран: он несёт имя, подпись и кнопку.
   Один фрагмент для всех — единственный способ сравнивать честно.

## Лестница

| Круг | Показываем | Пользователь |
|---|---|---|
| 1 | 30 вариантов | отмечает понравившиеся (обычно 3–5) |
| 2 | выбранные + 15 новых | отмечает (обычно 5) |
| 3 | выбранные + 10 новых | отмечает финалистов |
| 4 | финалисты | реализуются в коде |

Числа — рецепт, а не догма, но порядок держи: каждый круг примерно вдвое уже
предыдущего. **Выбранные всегда остаются на экране якорями** — рядом с ними видно,
куда сместился новый круг.

## Правила генерации

**Варианты отличаются родом, а не оттенком.** Это главное правило и главная
ловушка. Четыре палитры, разведённые на несколько тонов, — не четыре варианта, а
один. Каждый вариант должен отвечать на вопрос «а что если решать это совсем
иначе»: другая композиция, другой носитель метафоры, другая типографика, другой
способ дать глубину.

**Черпай из мира предмета.** Самые сильные варианты приходят не из вкуса, а из
материала: у дата-инженера это партиции, DAG, тепловая карта нагрузки, чек из
магазина; у пекарни — тесто, печь, бумага. Абстрактная красота проигрывает
предметной точности.

**Расширяй набор средств.** Не только цвет и шрифт: градиент и свет, узор и
растр, сетка и ритм, фактура материала, печатные традиции, анимация, фигуры,
фотография или иллюстрация из открытых источников. Круг из тридцати цветовых
схем — плохой круг.

**Обходи штампы.** ИИ-дизайн сам собой сваливается в три вида: кремовый фон с
контрастной антиквой и терракотовым акцентом; почти чёрный фон с одним кислотным
акцентом; газетная вёрстка с волосяными линейками. Каждый из них уместен, если
его попросили, но как выбор по умолчанию — это отсутствие выбора.

## Экран

Девять карточек на экран, сеткой 3×3 во всю высоту, зазоры минимальные — вариант
должен быть виден, а не подпись к нему. Тридцать вариантов это примерно три
экрана прокрутки.

Компаньон оборачивает фрагмент в свою рамку; чтобы сетка встала во весь экран,
пиши **полный документ** — файл, начинающийся с `<!DOCTYPE`, сервер отдаёт как есть.

```html
<!doctype html><html><head><meta charset="utf-8"><style>
  body{margin:0;background:#111;font-family:system-ui,sans-serif}
  .g{display:grid;grid-template-columns:repeat(3,1fr);grid-auto-rows:33.33svh;gap:2px}
  .v{position:relative;overflow:hidden;min-height:0}     /* сюда сам вариант */
  .cap{position:absolute;left:8px;bottom:7px;z-index:5;font-size:11px;
       padding:3px 8px;border-radius:99px;background:rgba(0,0,0,.55);color:#fff;
       backdrop-filter:blur(4px)}
  .v.pick{outline:2px solid #6ee7b7;outline-offset:-2px}  /* отметка выбора */
</style></head><body><div class="g">
  <div class="v" data-choice="01" onclick="toggleSelect(this)">…<span class="cap">01 · Название</span></div>
</div></body></html>
```

Подпись — номером и коротким именем прямо на карточке. Развёрнутое описание держи
в сообщении, а не на экране: экран для картинок.

## Расширенный режим: выбор на боевом хосте

Вкладка-компаньон живёт на `localhost` — с телефона в неё не зайти, коллеге не
показать, и варианты видно в вакууме, а не в реальном окружении. Когда сайт уже
где-то развёрнут, выкладывай экран выбора **туда же, по скрытому пути**.

**Как устроено.** Обычный статический файл рядом с сайтом, по неугадываемому
адресу вида `/_d/<случайный-токен>/index.html`. Никакого бэкенда: путь не
угадывается, ссылок на него нет.

1. Сгенерируй токен: `openssl rand -hex 8`.
2. Положи экран в `<корень>/_d/<токен>/index.html`, в `<head>` —
   `<meta name="robots" content="noindex,nofollow">`.
3. Добавь путь в манифест выкладки и запушь — дальше работает обычный деплой.
4. Отдай пользователю полную ссылку. Открывается с любого устройства.

**Предпросмотр вариантов на живом сайте.** Сильнее сетки макетов: научи саму
страницу принимать вариант параметром — `?design=<id>` — и применять его поверх
сохранённого выбора. Тогда пользователь смотрит не мокап, а настоящий сайт со
своим содержимым, прокруткой и на своём телефоне. В экран выбора добавь на каждую
карточку ссылку «открыть вживую» с этим параметром.

```js
// приоритет: ?design= из адреса → сохранённый выбор → основной набор
const fromUrl = new URLSearchParams(location.search).get('design');
```

**Возврат выбора — номерами в чат.** Не строй приём ответа с бэкендом: экран
показывает номера, пользователь называет их словами. Это одна строка вместо
сервера, формы и хранилища.

**Уборка.** После финала убери путь из манифеста и запушь — файл уедет с сервера
вместе с деплоем. Скрытый адрес не должен пережить воронку.

## Между кругами

1. **Прочитай выбор** — `$STATE_DIR/events` плюс текст пользователя в терминале.
2. **Назови вслух общую ДНК.** Это ядро метода: сформулируй одной-двумя фразами,
   что объединяет выбранное — «свет как приём, глубина слоями, ни одной яркой
   краски». Формулировка проверяется пользователем и становится рамкой круга.
   Заодно назови, что **выпало**: если из выбора ушли все варианты со структурой,
   структуры в следующем круге быть не должно.
3. **Строй новый круг из ДНК**, разводя варианты внутри неё: меняй направление
   источника, светлоту, температуру, плотность, гибридизируй выбранные между собой.
4. **Нумерация сквозная.** Вариант 26 остаётся двадцать шестым во всех кругах —
   иначе пользователь и ты говорите о разном.

## Комментарий автора

К каждому кругу давай короткую честную оценку от себя: какие варианты самые
характерные, какие безопасные, какие развалятся за пределами первого экрана.
Пользователь выбирает глазами — но риски видит тот, кто это будет исполнять.

## Анти-паттерны

- **Круг из оттенков одного решения.** Признак: описания вариантов отличаются
  только прилагательными цвета. Переделывай круг, не показывай.
- **Показ без якорей.** Новый круг без выбранных вариантов рядом лишает
  пользователя точки отсчёта.
- **Молчаливая ДНК.** Если не сформулировал общее вслух — следующий круг
  окажется случайным, и воронка не сузится.
- **Реализация до финала.** Пока круги идут, код не трогаем: правится только
  экран с вариантами.

## Выход

- Один-два финалиста, названные номером и именем.
- Сформулированная ДНК — она же становится описанием стиля в коде и в спеке.
- Тег с исходным состоянием, чтобы откатиться.
- Дальше — реализация: `frontend-design` для исполнения выбранного направления.
