# rnd-journal

Журнал R&D-исследований как память: тред на направление, внутри — вопрос
исследования, гипотезы, эксперименты, выводы. Скилл-процесс: пишется по ходу
работы, отвечает на «что я уже пробовал» без раскопок по чатам и папкам.

Все пути — относительно директории скилла (`SKILL_DIR`; symlink разрешай через реальный путь).

## Протокол данных (ОБЯЗАТЕЛЬНО, в начале и в конце)

`data/` живёт на git-ветке `data` (пушится только в приватный remote `private`; в публичном `main` директория пустая).

1. **Перед работой:** `git -C "$SKILL_DIR/../.." pull private data`. Если remote `private` нет или `data/INDEX.md` отсутствует (свежая установка) — работай локально, создай `data/INDEX.md` при первой записи.
2. **Сразу после записи:** `git add skills/*/data && git commit -m "data(rnd-journal): <slug>: <суть>" && git push private data`. На ветке `data` коммитятся только `skills/*/data/**` (pre-commit hook). Код скилла правится на `main`, затем merge `main→data`.

Коммить каждую содержательную запись отдельно — git log по `data/` и есть хронология журнала, руками её не веди.

## Структура данных

```
data/
├─ INDEX.md              # реестр тредов: slug, статус, вопрос, 1-2 строки сути, связи
└─ threads/<slug>/
   ├─ THREAD.md          # см. шаблон ниже
   └─ artifacts/         # планы, замеры, выгрузки (по необходимости)
```

Шаблон THREAD.md:

```markdown
# <Название треда>

> Вопрос исследования: <один вопрос, на который тред ищет ответ>
> Статус: active | paused | done · Начат: YYYY-MM-DD

## Гипотезы
- H1 (YYYY-MM-DD): <формулировка> — статус: открыта / подтверждена / опровергнута (→ эксперимент)

## Эксперименты
### E1 (YYYY-MM-DD): <что делали>
Сетап → результат → что это значит для гипотез.

## Выводы
- (YYYY-MM-DD) <вывод, на который можно опереться в будущем>

## Открытое
- <следующие шаги, нерешённые вопросы>

## Связи
- [<slug>](../<slug>/THREAD.md) — <как связан>
- разбор: [<название>](../../../youtube-breakdown/data/breakdowns/<slug>/OVERVIEW.md)
```

## Режимы

### Запись («зафиксируй…», «заведи тред»)
1. Протокол данных (pull) → прочитай `data/INDEX.md`.
2. Найди тред по теме; нет подходящего — создай `threads/<slug>/THREAD.md` по шаблону (slug — короткий kebab) и зарегистрируй в INDEX.
3. Допиши запись в нужную секцию с датой. Гипотезу при подтверждении/опровержении не переписывай — меняй статус и ссылайся на эксперимент: история рассуждений ценна.
4. Обнови строку треда в INDEX (суть/статус/связи, если изменились) → commit+push.

### Вспоминание («что я пробовал про X», «статус исследований»)
Двухэтапная загрузка: сначала только `data/INDEX.md`, выбери релевантные треды → читай их THREAD.md; artifacts — только если ответа нет в треде. Для хронологии («что делал в июне») — `git log --oneline -- skills/rnd-journal/data`. В ответе ссылайся на треды.

### Кросс-связи
Данные скиллов живут в одном репо: связывай треды с разборами youtube-breakdown относительными путями (секция «Связи»). При записи вывода, который пришёл из разбора ролика, — ставь ссылку в обе стороны не надо, достаточно из треда на разбор.

## Анти-паттерны
- Не веди хронологический журнал руками — его даёт git log.
- Не дублируй содержимое артефактов в THREAD.md — клади файл в artifacts/ и ссылайся.
- Не своди тред к списку ссылок: главное — гипотезы и выводы своими словами.
- Не заводить тред на каждую мелочь — сперва посмотри INDEX, мелкое чаще всего запись в существующем треде.
- Не коммить данные на `main`, не пушь `data` в `origin` — хуки блокируют, не обходи.
