# skill-audit

Аудит существующего скилла по нашему канону. Только **оцениваю** и предлагаю
правки — файлы меняю лишь по явной просьбе.

## Что нужно на входе
Путь к директории скилла (с `SKILL.md`) или несколько. Если не задан — спроси
или просканируй `~/.claude/skills` (учти: многие записи там — симлинки).

## Шаг 1. Собрать факты (детерминированно)
Для каждой директории `$DIR`:
```bash
find "$DIR" -type f | sort | while read f; do printf "%6s  %s\n" "$(wc -l <"$f")" "${f#$DIR/}"; done   # файлы + длины
awk '/^---[[:space:]]*$/{c++;print;next} c==1{print} c==2{exit}' "$DIR/SKILL.md"                          # frontmatter
awk '/^description:/{f=1} f{print} /^[a-z].*:/&&!/^description:/&&f&&NR>1{exit}' "$DIR/SKILL.md" | wc -m   # объём description
```

## Шаг 2. Оценить по двум осям

**ОПИСАНИЕ (description)**
- [ ] 3-е лицо, начинается с «Use when…» / «Используй, когда…»
- [ ] есть и WHAT, и WHEN
- [ ] дискриминирующие ключевые слова (те, которыми задачу сформулирует пользователь)
- [ ] ≤1024 символа; `name` ≤64, lowercase-with-hyphens
- [ ] граница с соседними скиллами обозначена

**КОМПАКТНОСТЬ**
- [ ] по умолчанию один `SKILL.md` (< ~500 строк)
- [ ] каждый доп. файл проходит критерий выноса: reuse / крупный редкий справочник (>~100 строк) / исполняемый скрипт
- [ ] нет дублирования тело ↔ `reference/*`
- [ ] нет пустых папок «на вырост»
- [ ] тяжёлое — на 3-м уровне, тело лёгкое

## Шаг 3. Анти-паттерны (флагуй явно)
Размытое `description` без WHEN/триггеров · преждевременное дробление
(50-строчный скилл на 6 файлов) · дублирование тело↔reference · гигантские
блоки кода в теле вместо ссылки на скрипт · пустые папки.

## Выход
По каждому скиллу: **вердикт** (эталон / доработать / переписать) → найденные
проблемы → конкретная правка (например, переписанный текст `description`).
Кратко, списком или таблицей. Файлы не трогать без явной просьбы.
