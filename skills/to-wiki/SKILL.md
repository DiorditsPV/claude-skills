# to-wiki

Документирует существующий предмет — витрину, инфраструктуру, код, чужой документ,
сравнение источников — и публикует в Confluence. Разделы выводит из предмета, а не
берёт из шаблона; текст пишет как описание текущего состояния.

## Когда применять
- Просят описать в вики то, что уже есть, и подтвердить описание фактурой.
- Просят обновить существующую страницу под новое состояние предмета.
- НЕ для свободной прозы без фиксированного места публикации (→ `technical-writer`)
  и не для самодостаточной веб-страницы (→ `present-html`).

## Правила текста

1. **Самостоятельный документ, а не дневник.** Состояние — как факт. Никаких «что
   изменилось», «перепроверено против прежней редакции», отсылок к прошлым версиям
   самой страницы. Даты и версии — идентификатор факта (редакция источника, номер
   задачи), не хронология. Повторная выверка = **переписать**, а не дописать.
2. **Уровень абстракции — предмет, а не реализация.** Не тащи имена классов, пути к
   файлам с номерами строк, имена констант, коммит-хеши (вместо них — номер задачи).
   Имена таблиц, колонок, сред, веток — оставляй, это и есть предмет. Выражения кода
   переводи в слова: `coalesce(…, 0)` → «не может быть пустым, иначе 0».
3. **Открытые вопросы — отдельным разделом внизу**, каждый своим `warning`-макросом;
   во вводной одна строка «Открыты N вопросов — см. в конце». Не разбрасывай их по
   тексту: то, что требует решения, читают списком.
4. **Перечисления построчно.** Три и больше элементов — список, один в строке, а не
   перечисление через запятую внутри предложения.

## Скелет страницы

Обязательного всего три: **открытие** (что это и зачем читателю + опорные факты и
строка про открытые вопросы), **фактура** (чем подтверждено — сэмпл, выдержка,
результат запроса; может отсутствовать, но это решение, а не забывчивость) и
**открытые вопросы** внизу.

**Между открытием и вопросами готовых разделов нет.** Середину выводи двумя вопросами:

- *из чего предмет состоит* — даёт таблицу или список, где **одна строка = одна
  единица** (колонка, поле, шаг, ветка, расхождение);
- *что читатель сделает не так без этой страницы* — ответ и есть раздел правил.

Самопроверка: сменился бы набор заголовков, будь предмет другого рода? Нет — значит
применён шаблон, а разделы не выведены. Куда приводит вывод:

- таблица БД → «Структура» · «Как правильно отбирать данные» · «Сэмпл»;
- сверка описаний → «Что с чем сравнивается» · «Совпадения» · «Расхождения».

Эти три — проверочные вопросы, не оглавление. Заголовки называй словами предмета;
разделов не больше, чем вопросов у читателя.

## Процесс

1. **Вход и место.** Предмет, space и родитель (дефолт — личный space); одна страница или «обзор + дети» — по числу самостоятельных объектов.
2. **Сбор фактуры.** По разделу ниже; ничего не пиши по памяти.
3. **Разделы.** Выведи по «Скелету» и покажи список заголовков пользователю до написания текста.
4. **Текст и публикация.** По «Правилам текста»; разметка — `reference/confluence-storage.md`.
5. **Верификация.** Перечитай опубликованное: макросы получили `ac:macro-id`, expand разворачивается, дочерние видны, вложенные списки не схлопнулись.
6. **Отчёт.** Ссылки из ответа API, охват, что осознанно не документируется, недоступные объекты, число открытых вопросов.

## Сбор фактуры

- Перечисли объекты и **проверь доступ к каждому отдельно** — права выдаются по
  объекту, а не по контейнеру; в алиасных пространствах имён гранты различаются.
- **Классифицируй, потом подтверди фактурой.** Не подтвердил — пиши
  «предположительно» и ставь `warning`-плашку, а не умалчивай.
- Недоступный объект получает **урезанный вариант страницы**: плашка «доступа нет,
  семантика не подтверждена» + метаданные, без фактуры.
- Родительская страница дерева содержит список «что осознанно не документируется».
- Сканы сужай: агрегаты по свежему диапазону, фильтр литералом, а не подзапросом.

### Сценарий: схема БД (Trino)

Правило, верное только для этого сценария, живёт здесь; верное для трёх разных
предметов — поднимается в общую часть выше.

- Вход `каталог.схема`; структуры из `information_schema.tables/columns`.
- Доступ потаблично: `SELECT count(*) FROM (SELECT * FROM t LIMIT 1)`. Если схема
  видна через несколько алиасных каталогов — пробуй каждый; `$partitions` часто закрыт.
- Версионность по служебным колонкам, подтверждённая данными: метка потока без флага
  удаления → снапшотная (проверь по 2–4 последним потокам); метка потока плюс флаг
  удаления или колонка конца интервала → CDC-инкремент; служебных колонок нет →
  справочник.
- Объёмы одним агрегатом: `count(*)`, `approx_distinct(<метка потока>)`, `min/max`.
- Сэмплы — `scripts/export_samples.py`; срез по литералу `<метка потока> = timestamp '…'`
  (подзапрос убивает прунинг), 15 строк по умолчанию, выравнивание только форматтером.
- Ширина: смотри `md_width` в `_report.json`; больше ~250–300 символов — проговори
  `--rows` и `--drop-cols` (в первую очередь широкие хэш-ключи). Сэмпл инлайном.

## Публикация

Канал по умолчанию — Confluence MCP; при его отказе или для вложений — REST
`<confluence-host>/rest/api` из CDP-браузера с SSO (`scripts/wiki_api.mjs`, браузер
поднимает `cdp-browser`).

Сырая storage-разметка проходит через markdown-конвертер MCP насквозь: макросы
вставляй прямо в markdown-контент, готовые куски — `reference/confluence-storage.md`.
PUT требует `version.number + 1`; дубликат заголовка в space — ошибка; ссылку бери
из ответа API.

## Грабли
- Markdown-конвертер **схлопывает вложенные списки** — иерархия «пункт → подпункты»
  теряется; делай подзаголовок или пиши фрагмент storage-разметкой.
- Кириллица в заголовках работает, но ссылку руками не собирай.
- Права проверяй на каждый объект, не на контейнер.
- Повторная выверка — переписать страницу, а не дописать changelog.

## Выход
- Страница или дерево в Confluence, фактура инлайном, вопросы `warning`-макросами внизу.
- Локально — сэмплы и выгрузки в каталоге выгрузок по контексту проекта.
- Отчёт: ссылки, охват, карта доступа, число открытых вопросов.
