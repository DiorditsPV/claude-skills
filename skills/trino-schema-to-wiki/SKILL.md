# trino-schema-to-wiki

Документирует Trino-схему в Confluence: структуры + версионность + сэмплы →
дерево страниц.

## Когда применять
- Просят «задокументировать источник/схему/витрины» с сэмплами данных.
- Нужны страницы таблиц с правилами «как правильно отбирать данные».
- НЕ для источников вне Trino и не для свободной прозы (→ `technical-writer`).

## Процесс

1. **Вход и место.** Уточни `каталог.схема` (и список таблиц, если не вся схема).
   Спроси space/родителя в wiki; дефолт — личный space пользователя. Структура:
   родительская страница схемы + дочерние по одной на таблицу.
2. **Разведка.** `information_schema.tables/columns` через Trino MCP. Карту
   доступа строй **потаблично**: `SELECT count(*) FROM (SELECT * FROM t LIMIT 1)`
   на каждую (гранты в ACL per-table). Если схема доступна через несколько
   алиасных каталогов — пробуй каждый, гранты на них могут различаться;
   `$partitions` часто закрыт.
3. **Профиль версионности** (только доступные таблицы) — классифицируй по
   служебным колонкам загрузки и подтверди данными:
   - метка потока загрузки без флага удаления → **снапшотная**: проверь
     группировкой по 2–4 последним потокам (равномерные полные срезы,
     стабильное число ключей);
   - метка потока + флаг удаления или колонка конца интервала → **CDC-инкремент**;
   - служебных колонок нет → **справочник**.
   Объёмы: `count(*)`, `approx_distinct(<метка потока>)`, `min/max` — одним
   агрегатом на таблицу; потоковые разрезы фильтруй по свежему диапазону
   (партишн-прунинг), не по всей истории.
4. **Сэмплы.** `scripts/export_samples.py` (см. «Форматирование сэмплов»).
   Срез — последний снапшот, фильтр по **литералу**
   `<метка потока> = timestamp '…'` (не подзапросом — иначе нет прунинга).
5. **Страницы.** Канон — раздел «Формат описания». Канал: Confluence MCP, при
   его отказе или нужде в макросах/вложениях — REST `<confluence-host>/rest/api`
   из CDP-браузера с SSO (`scripts/wiki_api.mjs`, браузер — скилл `cdp-browser`).
   PUT требует `version.number + 1`; дубликат заголовка в space — ошибка.
6. **Верификация.** Перечитай родительскую страницу, проверь, что дочерние
   видны и сэмплы развернутся (CDATA не побит).
7. **Отчёт.** Ссылки на страницы, таблица «страница / строк в снапшоте / всего»,
   список закрытых ACL (и что по ним нужна заявка на гранты).

## Формат описания (канон страницы таблицы)

Разделы в этом порядке:

1. **Вводный абзац** — смысл таблицы своими словами + цифры: строк в снапшоте,
   всего истории, с какой даты, частота загрузки, число ключей.
2. **Расположение** — FQN `каталог.схема.таблица` + ссылка на карточку во
   внутреннем каталоге данных, если он есть.
3. **Структура** — таблица «Колонка | Тип | Смысл», **одна строка = одна
   колонка**, в «Смысл» — живые примеры значений из сэмпла. Если в схеме есть
   парные колонки «бизнес-код источника» и «суррогатный ключ DWH» — перед
   таблицей абзац о том, что это разные колонки: джойны между витринами идут по
   суррогатному ключу, сверка с источником — по бизнес-коду.
4. **Как правильно отбирать данные (историчность и версионирование)** — класс
   таблицы из шага 3 процесса + SQL-шаблоны: актуальный срез, as-of на момент
   времени, динамика по дням (один снапшот в день). Обязательное предупреждение
   про дубли без фиксации снапшота. Не подтверждено данными (нет доступа) —
   пиши «предположительно» и warning-плашку.
5. **Сэмпл данных** — expand-макрос с выровненной markdown-таблицей (ниже).
6. Курсивная пометка о генерации и дате.

Страница ACL-закрытой таблицы: warning-плашка (SELECT закрыт, структура из
information_schema, семантика не подтверждена) + разделы 1–4 без сэмпла.

Родительская страница: обзор схемы, механика загрузки, две группы таблиц
(доступные / закрытые ACL), что не документируется (бэкапные и тестовые таблицы
по принятому в схеме префиксу/суффиксу).

## Форматирование сэмплов

- Дефолт: **15 строк** (диапазон 10–20), из последнего снапшота.
- Выравнивание — **внешним форматтером**, не руками: `tabulate`,
  `tablefmt="github"`, `disable_numparse=True` (тот же принцип, что
  markdown-table-форматтеры VS Code). Скрипт делает это сам.
- На странице: `expand`-макрос («Сэмпл N строк из снапшота <dttm>») →
  `code`-макрос `language=markdown`. В CDATA экранируй `]]>`.
- Вложения (xlsx) не использовать — сэмпл живёт инлайном.
- Настройки по необходимости (проговори с пользователем, если ширина строки
  переваливает ~250–300 символов): число строк (`--rows`), исключение широких
  малоинформативных колонок — в первую очередь хэш-ключей (`--drop-cols`),
  укорачивание значений.

## Грабли
- Права проверяй на **каждую** таблицу и на алиасных каталогах — карта доступа
  неоднородна.
- Агрегаты по многомиллиардным таблицам без фильтра по метке потока — долгие
  сканы; всегда сужай диапазон.
- `count(*)` по вьюхам может быть дорогим — для них хватит `LIMIT`-сэмпла.
- Кириллица и спецсимволы в заголовках страниц — ок, но ссылку бери из ответа
  API, не составляй руками.

## Выход
- Дерево страниц в Confluence (родитель + по таблице), сэмплы инлайном.
- Локально: CSV/markdown сэмплы в каталоге выгрузок по контексту проекта.
- Отчёт со ссылками и картой доступа.
