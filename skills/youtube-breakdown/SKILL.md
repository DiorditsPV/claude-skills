# youtube-breakdown

Разбор YouTube-ролика: yt-dlp → чистый транскрипт → выверка по первоисточнику → `OVERVIEW.md`.
Скилл-процесс: разборы копятся в `data/` и служат памятью — каждый новый разбор
связывается с прежними, по накопленному можно отвечать на вопросы без пересмотра роликов.

Все пути ниже — относительно директории скилла (`SKILL_DIR`, где лежит этот файл; symlink разрешай через реальный путь).

## Когда применять
- «разбери этот ролик», «сделай разбор видео <url>», «что в этом видео — выкачай субтитры»;
- «что я смотрел про <тема>», «в каком ролике было про <X>», «сравни подходы из <ролик A> и <ролик B>» — ответ из `data/` без скачивания;
- нужен конспект/анализ доклада или туториала без просмотра видео.

## Протокол данных (ОБЯЗАТЕЛЬНО, в начале и в конце)

`data/` живёт на git-ветке `data` (пушится только в приватный remote `private`; в публичном `main` директория пустая).

1. **Перед работой:** `git -C "$SKILL_DIR/../.." pull private data` (репо — корень над `skills/`). Если remote `private` нет или `data/INDEX.md` отсутствует (свежая установка из marketplace) — работай локально и создай `data/INDEX.md` при первом разборе.
2. **Сразу после работы:** `git add skills/*/data && git commit -m "data(youtube-breakdown): <slug>" && git push private data`. На ветке `data` коммить только файлы `skills/*/data/**` — pre-commit hook отклонит остальное. Код скилла правится на `main`, затем `merge main→data`.

## Процесс разбора

### 1. Память: INDEX.md
Прочитай `data/INDEX.md` — реестр всех разборов. Он нужен дважды: чтобы не разбирать уже разобранное и чтобы в конце связать новый разбор с прежними.

### 2. Директория и слаг
Слаг — короткое kebab-имя по теме ролика (напр. `loop-engineer`), не по полному заголовку. Рабочая папка: `data/breakdowns/<slug>/`.

### 3. Скачивание (без видео)
```bash
yt-dlp --skip-download \
  --write-info-json --write-description \
  --write-auto-subs --sub-langs "en.*,ru.*" \
  -o "<dir>/<slug>.%(ext)s" "<url>"
```
Даст `<slug>.info.json`, `<slug>.description`, `<slug>.<lang>.vtt` (+ `<lang>-orig.vtt`). Если есть ручные сабы — добавь `--write-subs`. Если сабов нет вовсе — сообщи пользователю и остановись.

### 4. Транскрипт
```bash
python3 "$SKILL_DIR/scripts/vtt_to_transcript.py" \
  "<dir>/<slug>.en.vtt" "<dir>/<slug>.transcript.txt"
```
Прочитай результат целиком. Из `info.json` возьми только шапку: `title`, `channel`, `duration_string`, `upload_date`, `webpage_url` (файл огромный — не читай весь, используй `jq`).

### 5. Внешние артефакты (если есть)
Проверь `<slug>.description`: если автор ссылается на ключевой артефакт (GitHub-репо, шаблон, документ) — выгрузи его существенные файлы в `<dir>/repo/` (например `gh api` / `git clone --depth 1` + копирование README, доков, скиллов). Терминологию и названия в разборе выверяй по артефакту, а не по сырому ASR (авто-сабы искажают термины: «claw» → Claude, «ripple» → repo и т.п.). Рекламные/партнёрские ссылки артефактом не считаются.

### 6. OVERVIEW.md
Пиши на русском, англ. термины сохраняй. Структура (адаптируй под контент, эталон — `data/breakdowns/loop-engineer/OVERVIEW.md`):

1. **Шапка** — цитата-блок: название, канал/автор, URL, длительность, дата публикации, из чего собран разбор.
2. **Артефакты** — ссылки, репозитории, инструменты из видео и описания + список локально сохранённого.
3. **Суть** — главная идея в 3–5 абзацах.
4. **Основные разделы** — ключевые концепты/компоненты/шаги по логике ролика (не пересказ по хронологии, а структура смысла).
5. **Практические тезисы** — что стоит забрать, списком.
6. **Связь с прежними разборами** — по `INDEX.md`: что развивает, чему противоречит, с чем пересекается (со ссылками на `../<slug>/OVERVIEW.md`). Если пересечений нет — так и напиши.
7. **Связь с проектами пользователя** — если тема пересекается с известными проектами, отметь пересечение, но не лезь в них без запроса.
8. **Источники**.

### 7. Обновить INDEX.md
Добавь/обнови запись: слаг, название, автор/канал, дата публикации ролика, дата разбора, 1–2 строки сути, теги, кросс-ссылки на связанные слаги. Формат — по существующим записям.

### 8. Финал
Выполни протокол данных (commit+push). Покажи пользователю путь к папке и краткое резюме разбора (3–5 пунктов), включая найденные связи с прежними разборами.

## Ответы по накопленным разборам (без нового ролика)
Двухэтапная загрузка: сначала только `data/INDEX.md`, по нему выбери релевантные слаги → читай их `OVERVIEW.md`; сырые транскрипты подтягивай только если ответа нет в разборе. В ответе ссылайся на конкретные разборы.

## Анти-паттерны
- Не скачивай видео/аудио — только сабы и метаданные.
- Не пересказывай хронологически «а потом он сказал» — структурируй по смыслу.
- Не переноси в разбор спонсорские вставки (кроме строки в «Артефактах», если уместно).
- Не доверяй терминам из ASR, когда есть чистый источник (описание, репо).
- Не коммить данные на `main` и не пушь ветку `data` в `origin` — хуки это блокируют, не обходи их.
